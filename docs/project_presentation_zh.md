# ML-Project-group4 项目介绍演讲稿

建议时长：4 到 6 分钟

各位老师、同学大家好，我们是第四组。今天我们介绍的项目是一个面向视频会议、访谈和演讲素材的多模态脚本修复 Agent，项目名称是 ML-Project-group4。

这个项目想解决的问题很直接：当我们把一段视频交给自动语音识别系统时，模型通常可以生成一份初步转写稿，但这份稿件并不总是可靠。尤其是在音频质量受损、背景噪声较大、说话人较多，或者内容中出现大量人工智能、机器学习等专业术语时，ASR 很容易把关键词识别错。比如专有名词、技术术语、幻灯片上的文字，单靠音频模型不一定能准确还原。

所以我们的核心思路是：不要只相信单一音频信号，而是把音频、画面信息和外部知识结合起来，让系统在修复文本时有更多证据可以参考。

整个项目可以理解为一条“视频到结构化脚本”的处理流水线。第一步，系统使用 ffmpeg 从视频中抽取音频，并进行高通滤波和响度归一化，尽量提升后续识别质量。第二步，系统调用 WhisperX 完成语音识别，生成分段文本、词级时间戳，并根据词置信度标记可能出错的片段。第三步，系统会从视频中抽取关键帧，包括固定间隔抽帧、场景变化抽帧，以及低置信度语音片段附近的补充抽帧。第四步，视觉模型会分析这些帧，提取画面场景、人物动作、屏幕文字和潜在术语。第五步，RAG 模块会从本地术语表中检索相关背景知识，例如术语别名、常见误听写法和来源信息。最后，系统将 ASR、视觉证据和 RAG 证据按时间对齐，交给文本模型进行谨慎修复，并导出 JSON 和 Markdown 两种格式的结果。

这个方案的特点是“证据驱动”。我们不是让大模型自由改写，而是要求它保留原始时间戳和说话人标签，只在证据支持时修正文本。如果某个片段置信度较低，或者修复依据不足，系统会把它标记为需要人工复核。这样做可以降低幻觉风险，也更适合课程项目、会议纪要、字幕整理等需要可追溯结果的场景。

在数据方面，我们整理了 10 个 TED 和 TED-Ed 中与人工智能、机器学习、深度学习、AI Agent 和信息误导相关的视频样本。每个样本包含视频、已抽取音频、人工整理的 ground truth transcript、元数据和 RAG 背景材料。这样既可以支持流水线演示，也方便后续做识别质量和修复效果评估。

从工程实现上看，项目采用模块化结构。所有核心模块都位于 `src/agent/` 目录，每个阶段都有独立的 `run()` 函数，便于测试和替换。CLI 入口负责把这些模块串联起来。我们也编写了单元测试，覆盖数据结构、音频处理、ASR 封装、抽帧、视觉解析、RAG 检索、证据合并、文本修复和导出逻辑。为了让项目更容易启动，我们还提供了 Makefile，用户可以通过 `make doctor` 检查环境，通过 `make sync` 安装依赖，通过 `make run` 启动一个轻量流程，也可以通过 `make run-full` 接入完整的视觉模型和文本模型 API。

目前项目仍处于第一阶段。它已经完成了主要流水线和可运行的 CLI，但还有一些限制：RAG 目前使用本地 JSON 术语表模拟，还没有接入真实向量数据库；流程由 CLI 顺序执行，还没有引入 LangGraph；也暂时没有 Web UI、批处理和 SRT/VTT 字幕导出。后续我们计划继续增强三个方向：第一，接入真实向量检索，让背景知识覆盖更广；第二，引入更系统的评估指标，对比原始 ASR 与修复后文本的质量；第三，扩展导出格式和交互方式，让结果更方便用于字幕、会议纪要和人工审核。

总结一下，我们的项目不是简单做一次语音转文字，而是构建了一个可解释、可扩展、证据驱动的多模态脚本修复框架。它把 WhisperX 的语音识别能力、视觉模型的画面理解能力、RAG 的知识补充能力和大语言模型的文本修复能力结合起来，目标是在复杂视频场景中生成更准确、更可追溯的结构化脚本。

以上就是我们的项目介绍，谢谢大家。
